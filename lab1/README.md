# Лабораторна робота 1. Ідеальне хешування

**Варіант 8, тип даних Т8 (завдання 1):** комплексні числа з цілочисельними компонентами.
Порядок: порівнюються модулі чисел; числа з однаковими модулями порівнюються за першою (дійсною) компонентою.

`Complex.h` - Власна реалізація комплексного числа з цілими компонентами та порядком за умовою |
`PerfectHashTable.h` - Ідеальне хешування — двохрівнева схема FKS (Фредман–Комлош–Семереді) |
`main.cpp` - Демонстрація + стрес-тести проти еталонної множини |

Ідеальне хешування будується для **статичної** множини з `n` ключів (CLRS, розд. 11.5):

1. **Перший рівень.** Універсальна хеш-функція `h(x, y) = ((a1·x + a2·y + b) mod p) mod n`
   (де `p = 2^31 − 1` — просте число Мерсенна, `x`, `y` — зсунуті в невід'ємний діапазон
   компоненти комплексного числа) розкидає ключі по `n` кошиках. Функцію перебираємо
   випадково, доки `Σ m_j² ≤ 4n` (`m_j` — розмір кошика `j`). За теоремою це виконується
   з імовірністю ≥ 1/2, тому очікувано потрібно ≤ 2 спроб.
2. **Другий рівень.** Кошик із `m_j` ключами отримує таблицю розміру `m_j²` і власну
   хеш-функцію з тієї ж сім'ї, яку перебираємо, доки вона не стане **ін'єктивною**
   (жодної колізії). Імовірність колізії при розмірі `m_j²` менша за 1/2, тому
   очікувано < 2 спроб на кошик.

**Властивості:**
- пошук — **O(1) у найгіршому випадку**: 2 обчислення хеш-функції та 1 порівняння;
- пам'ять — **O(n)** (контролюється межею `Σ m_j² ≤ 4n`);
- побудова — очікувано O(n).

Компоненти ключів обмежено діапазоном `[−10⁹; 10⁹]` (< p), тому різні числа дають різні
пари залишків за модулем `p`, а всі проміжні добутки вкладаються у 64-бітну арифметику.
